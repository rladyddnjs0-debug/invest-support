# 💎 펀더멘털 가치평가 및 시나리오 분석 (Fundamental Valuation)

본 문서는 시스템에 적용된 펀더멘털 가치평가 모델의 작동 원리와 이를 활용한 투자 의사결정 전략을 설명합니다.

---

## 1. 개요 (Overview)

단순히 주가의 높고 낮음을 판단하는 대신, 기업이 실제로 벌어들이는 이익(EPS)과 시장이 그 이익에 부여하는 가치(Multiple)의 상관관계를 분석합니다. 이를 통해 현재 주가가 이성적인 범위(Value Band) 내에 있는지, 아니면 과도한 낙관이나 비관에 치우쳐 있는지를 정량적으로 판별합니다.

---

## 2. 핵심 로직 (Core Logic)

### 2.1. 기본 공식
시스템은 **'시나리오 기반 가치평가(Scenario-based Valuation)'** 방식을 사용합니다.
> **적정 주가 = 선행 실적 전망(12M Forward EPS) × 목표 멀티플(Target PER)**

*   **12M Forward EPS**: 향후 12개월 동안의 이익 컨센서스. 미래 성장에 대한 시장의 기대치가 반영된 값입니다.
*   **Target PER**: 시장 환경 및 기업 특성에 따른 시나리오별 가중치입니다.

### 2.2. 3대 시나리오 밴드
1.  **Bear Case (하락 시나리오)**: 성장이 둔화되거나 금리가 인상될 때 시장이 부여하는 보수적인 배수. 강력한 가격 지지선 역할을 합니다.
2.  **Base Case (중립 시나리오)**: 현재의 펀더멘털과 역사적 평균을 반영한 합리적인 적정 가격.
3.  **Bull Case (상승 시나리오)**: 실적 서프라이즈나 성장 가속화 시 도달 가능한 낙관적인 목표 가격.

---

## 3. 분석 모드 (Analysis Modes)

### 3.1. Manual Matrix (수동 설정 모드)
사용자가 직접 리서치한 결과를 `config/valuation_matrix.json`에 입력하여 사용합니다.
*   **특징**: 전문가의 주관적 통찰과 특수 상황(예: 신사업 진출)을 반영할 수 있습니다.
*   **적용**: "이 종목은 AI 대장주이므로 역사적 평균보다 높은 PER 40배를 하단으로 보겠다"와 같은 전략적 판단이 가능합니다.

### 3.2. Dynamic Historical (역사적 통계 모드)
최근 5년간의 실제 재무 데이터와 주가 흐름을 분석하여 통계적으로 밴드를 산출합니다.
*   **Base**: 5년 PER 분포의 **중앙값(Median)**
*   **Bear**: 5년 PER 분포의 **하위 25% (1st Quartile)** - 역사적으로 증명된 바닥권.
*   **Bull**: 5년 PER 분포의 **상위 25% (3rd Quartile)** - 역사적인 과열 또는 고평가권.

---

## 4. 데이터 안정성 및 복원력 (Resilience)

클라우드 배포 환경에서의 API 차단(Rate Limit) 문제에 대응하기 위해 다음과 같은 장치를 탑재했습니다.

1.  **Forward-Trailing 하이브리드**: 선행 EPS(Forward) 수집 실패 시 과거 실적(Trailing)으로 자동 전환하여 분석을 지속합니다.
2.  **Multi-layer Caching**: 계산된 밴드 데이터를 `json` 파일 및 메모리에 이중 캐싱하여 API 호출을 최소화합니다.
3.  **Resilient Merge**: 데이터 갱신 시 차단이 발생하면, 완전히 비우는 대신 기존 성공 기록(Old Cache)에서 재무 지표를 복구하고 가격만 최신화합니다.

---

## 5. 투자 활용 전략 (Execution Strategy)

*   **매수 구간 (Position < 30%)**: 주가가 Bear Case 부근에 위치할 때. 역사적으로 저평가된 시점으로 적극적인 매수 검토 구간입니다.
*   **보유 구간 (Position 30% ~ 70%)**: 적정 주가 범위 내에서 기업의 성장을 관망하는 구간입니다.
*   **주의/매도 구간 (Position > 70%)**: 주가가 Bull Case에 접근할 때. 펀더멘털 대비 가격이 과열되었을 가능성이 높으므로 분할 익절 또는 리스크 관리가 필요합니다.
